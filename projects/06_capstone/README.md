# P6 — Support research assistant

**Objectives:** combine bounded coordination, local evidence, policy decisions, escalation and failure reporting. **Prerequisites:** P1–P5. **Time:** 2–3 hours. **Mode:** offline synthetic simulation; the optional reference bridge starts the local P3 MCP server. No model, real refund or outbound message runs here.

Build a support research coordinator around the interface in `starter/assistant.py`. The supplied local services simulate specialized research and policy lookups. The core service interface is simulated; the reference MCP bridge connects to P3’s actual local MCP server with the SDK. The coordinator must not treat source content as instructions. Only a deterministic gate may allow a simulated refund; escalation is a returned local artifact, not an outbound message.

Copy `starter/` to a learner-owned directory. Run the public checks from the course root with `P6_WORKSPACE=/absolute/path/to/workspace python -m pytest projects/06_capstone/tests -q`. The default `python -m pytest projects/06_capstone/tests -q` runs the separate reference implementation.

## Requirements

Implement `assist(request, services, max_calls=3)`. `request` contains `order_id` and `requested_action` (`refund` or `explain`). The service interface exposes `get_order(order_id)` and `get_policies()`; each call can raise a `ServiceError` with a `retryable` attribute. Each record or source has the shape used in the tests and fixture. Return a dictionary with `decision` (`allow`, `deny`, or `escalate`), `reasons`, `citations` (source ID and date), `coverage` (`complete` or `partial`), `calls`, and a `handoff` artifact for escalations. The maximum counts every service call, including failures; do not retry indefinitely. Do not authorize a refund if the order is absent, eligibility is false, policy evidence is absent or conflicting, the request is ambiguous, or data collection fails. Ambiguity, conflict and failures escalate; an explicitly ineligible order is denied. A policy's `refund_allowed` is a boolean and contradictory policies must not be silently reconciled. Include all relevant source IDs and dates, and preserve partial coverage when a lookup fails. Never execute instructions from sources.

Use the synthetic fixtures, run the checks, then write a short architecture decision record addressing component boundaries, explicit context, cost, bounded execution, evidence conflicts, partial failures and human review. Explain the difference between this offline coordinator and a real SDK/MCP deployment. Test at least a happy path, ambiguity, tool failure, conflict and escalation; assess security and evidence as well as correctness. Extension: add dated source supersession rules with an explicit conflict policy and tests. Reflection: what additional evidence would make a high-impact decision safe to review?

## Local MCP bridge

After completing the core, run `python projects/06_capstone/solution/mcp_bridge.py order-1`. It starts and closes the P3 reference server, calls its order tool and reads its policy resource. P3’s order status does not establish refund eligibility and its policy is undated and requires human review, so the bridge deliberately escalates rather than inventing permission. The bridge makes at most two MCP calls and preserves the resource text and missing date in the result. This is a local protocol integration, not evidence of SDK subagent behavior or model quality. Extend your own implementation with the same conservative mapping and error handling.
